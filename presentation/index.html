Robustness layer

Guards — physical priors as hard constraints

Hand-coded physics rules — reshape emissions before the HMM, sanity-check labels after.

Pre-decode (before HMM)
GuardWhen it firesWhat it does
Low-motion gatebody_mag_energy < 0.1Removes all locomotion + transitions; only sit/lay & stand left
Stairs staticLow energy, low jerk, low dom freqCaps stairs probability
Stairs movingMoving but wrong rhythm for stairsSuppresses stairs using cadence/periodicity
Walk guardWindow looks like smooth walk but model favours run/stairsCaps run/stairs, boosts walk
HallucinationAbsurd energy/jerk with stairs probCaps stairs (pocket knock / artifact)
Post-decode (after HMM)
GuardWhat it does
Stairs failsafeDecoded stairs too high but raw walk/run support it → demote stairs
Locomotion ↔ transitionsHigh-energy “transitions” → really walk/run
Artifact calibrationNoisy/artifact window → lower confidence
Pocket sanityCadence/periodicity vs label (e.g. run with walk cadence → demote)
Fail-safe: physics rules, not learned — better to suppress impossible labels than report them confidently on bad signal.

Reliability

Failure modes

Ingest & sensor stream
If this happensSystem response
Worker falls behindInference queue capped (2 000 tasks); drop oldest task — favour fresh windows
Phone retries the same batchDedupe on session + device + message_id — accepted once, ignored after
Batches arrive out of orderTrack last message_id; resample still sorts points by timestamp
Gap or pause in uploadWindow needs ≥80% time coverage — else no-data; long stillness resets HMM state
Too few samples in windowReject early — no-data, never guess from a partial window
Inference, ops & isolation
If this happensSystem response
Implausible or noisy ML outputGuards reshape probabilities; artifact score calibrates confidence down
Worker container crashesCompose auto-restart; decoder state & snapshots live in Redis
Sessions or buffers grow foreverSession TTL + capped raw ring (6 000 pts) & history lists
Wrong session or device writes dataWrite token must match session + device in payload — else 403
Typed snapshots end-to-end: success · queued · no-data · no-features · model-error · prediction-error — the dashboard and phone UI show status + detail, not a blank screen.

Roadmap · edge

Running on an edge device

Same pipeline, not a redesign — prove parity stage-by-stage, then measure on real hardware.

flowchart LR
  IMU["IMU · 50 Hz"] --> RB["ring buffer"]
  RB --> WIN["128-sample window"]
  WIN --> PIPE["filter → features → trees → HMM"]
  PIPE --> OUT["label snapshot"]
  PIPE --> SLP["CPU sleep"]
  FLASH["flash: trees + constants"] -.-> PIPE
  RAM["RAM: buffers + session state"] -.-> PIPE

↓ Memory

  • Compact tree export to flash
  • Window-sized buffers only
  • Cap runtime / decoder state

↓ Compute

  • XGBoost trees are if/else statements
  • Infer on window ready, not per sample
  • Fixed-cost features · HW DSP if needed

↓ Power

  • Sensor FIFO · sleep between windows
  • Send labels, not raw sensor data
  • Signed OTA model updates
Rollout: parity in CI → measure on hardware → optimize → signed OTA.
